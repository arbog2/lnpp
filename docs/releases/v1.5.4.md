## LNPP 组件管理器 v1.5.4

新增 **PHP** 组件（FastCGI 多版本共存），并修掉三个现存缺陷——其中一个让你
**再也停不掉 nginx / PostgreSQL / Redis**。

### 新增：PHP 组件（FastCGI）

Windows 上**没有 PHP-FPM**，官方发行包唯一能接 FastCGI 的是 `php-cgi.exe`，
所以 PHP 按常驻组件建模：

```
bin\php\<版本>\php-cgi.exe -c data\php\<版本>\php.ini -b 127.0.0.1:<端口>
```

- **状态灯 = 端口有没有被绑定**。不 spawn 进程、不写 pid 文件，所以后台轮询
  线程调它也是安全的（这正是审查报告 P1-7 那类 UI 线程冻结的根因）
- **停止按镜像路径校验归属再杀**。只看进程名会杀掉用户自己在外面起的
  php-cgi——和 nginx 当年「认领别人的 nginx master」是同一类错
- 进程被手工重启也能正确反映状态（因为判据是端口而不是 pid）

#### 多版本共存

这是 PHP 和其他四个组件最大的不同：**所有已安装版本同时运行**，各占一段连续
端口。A 项目要 8.1、B 项目要 8.3 可以并存。

| settings.ini 键 | 含义 |
|---|---|
| `ver.php` | 默认版本，只决定新建站点默认选中谁 |
| `php.baseport` | 端口分配起点，默认 9000 |
| `php.verport.<版本>` | 该版本第一个 FastCGI 端口 |
| `php.workers.<版本>` | 该版本的 php-cgi 进程数，1–32，默认 1 |

端口**只在启动该版本时分配**，分配后写进 ini 永不重摇——站点配置里已经写死了
后端。**删掉 8.1 不会让 8.3 漂移；把 8.1 装回来会拿回原来那段的第一个端口，
老站点配置继续有效。** 分配时保证整段区间（不是单个端口）不与其他版本重叠，
也不落在已被别的程序监听的端口上。

「切换版本」按钮对 PHP 的含义是**设为默认版本**，不会停掉其他版本。

#### 进程数就是并发能力

一个 php-cgi **串行**处理请求，所以进程数是全部并发能力：

- **进程数 = 1**：站点直接写 `fastcgi_pass 127.0.0.1:9000;`，不需要 upstream
- **进程数 > 1**：`genNginxConfig` 在 `http { }` 里生成一个 upstream，站点写
  `fastcgi_pass lnpp_php_8_1;`，由 nginx 轮询

> ⚠️ 自定义过 `etc\nginx\nginx.conf.tpl` 的话，**必须在 `http { }` 内、
> `include vhosts/*.conf;` 之前保留 `{{PHP_UPSTREAM}}` 这一行**。多进程版本缺了
> 它，upstream 不会生成，nginx 会以「unknown upstream」启动失败。管理器检测到
> 这种组合会在 `logs\lnpp.log` 里点名提示。

在 PHP 页签选中版本、改「进程数」再点「启动选中」即可生效，管理器会顺手重载
nginx 让站点改指向对应的 upstream。**只有全部进程都监听成功，该版本才显示
「运行中」**——半死不活的进程池比没有更糟，nginx 会继续往没起来的端口发请求。

#### php.ini 与扩展管理

首次启动某版本时生成 `data\php\<版本>\php.ini` = 发行版自带的
`php.ini-production` + 渲染后的 `etc\php\php.ini.append`。**只生成一次**——
「配置」按钮打开的就是这个文件。

`extension_dir` 写的是**绝对路径**：相对路径按进程工作目录解析，换个目录就
找不到 dll。

PHP 页签 →「扩展管理」：列出该版本 `ext\` 里的全部 dll，**以及 php.ini 提到
但该版本没附带的扩展**（PECL 的 redis / imagick / memcached 需要自己装 dll）。
这些通常只在启动时往 stderr 写一句警告，而 php-cgi 是 detach 启动的，根本没人
看得到——现在直接在列表里标出来。

写入**只重写 `extension=` / `;extension=` 那几行，其余每一行原样保留**，你写在
同一文件里的 `memory_limit` 和自定义设置都不会被动到。同一扩展在 ini 里出现
多次时每一次都改（php 取最后一次，只改第一处会让结果依赖行序）。

#### 站点对话框

「添加站点」多了**类型**（Node.js / PHP）。选 PHP 时才出现「PHP 版本」下拉，
**只列正在运行的版本**——指向没人监听的端口等于每个请求 502。站点列表也加了
「类型」列，PHP 站点显示成 `PHP 127.0.0.1:9000` 或 `PHP lnpp_php_8_1`，一眼
看得出后端是哪个。

## 修复

### 1. 启动后 nginx / PostgreSQL / Redis 再也无法启停

**这个最要紧。** 表现是管理器起来后，这三个组件的状态灯和文字都正常，但
**「停止」按钮永远是灰的**，怎么点都没用，重启管理器也未必好。

根因：`g_main = CreateWindowExW(...)` 这行赋值在 `CreateWindowExW` **返回之后**
才执行，而 `WM_CREATE` 是在 `CreateWindowExW` **内部**派发的，`autoStartComponents()`
就写在 `WM_CREATE` 里。它起的工作线程结束时调用
`PostMessageW(g_main, WM_OP_DONE, ...)`，此刻 `g_main` 还是 `nullptr`：

- `PostMessageW(NULL, ...)` 把消息投到**调用线程的消息队列**，不是窗口的
- 主循环 `DispatchMessageW` 拿到 `hwnd == NULL` 的消息，**直接丢弃**
- 于是 `ui.busy` 永远清不掉，该组件的启停按钮永久禁用

为什么有时看起来正常：**快的组件才中招**。nginx / PostgreSQL / Redis 走
「已在运行」秒退，线程结束时窗口还没建好；Node.js 的 `pm2 resurrect` 要两秒
左右，等它结束时 `CreateWindowExW` 早就返回了，所以它的按钮一直是好的。
你如果关掉所有组件再启动管理器，看起来又会「正常」——纯属时序巧合。

修法两处：`WM_CREATE` 第一行就 `g_main = hwnd;`；`autoStartComponents()` 移出
`WM_CREATE`，放到 `CreateWindowExW` 返回之后（本来就不该在窗口创建过程中起线程）。

顺带把「状态」和「按钮」判据不一致的问题也修了。之前状态列来自 2 秒轮询、
按钮禁用来自 `busy`，两者独立，于是出现**「运行中 1.30.4」配一个灰掉的
「停止」**——看起来像坏了。现在操作进行中时状态列显示「操作中…」、按钮显示
「…」，两者一致。

### 2. 自定义站点模板自 v1.5.3 起完全失效

`nginxAddVHostEx` 是从 `data\nginx\vhosts\` 读 `_template.conf` 的，但 v1.5.3
的目录重构把模板挪进了 `etc\`（迁移时明确 `continue` 跳过 `_template*`）。所以
它每次都读不到，一直在用内置的 `DEFAULT_VHOST`——**你在 `_template.conf` 里
做的任何修改，对新建站点都没有效果**。

更糟的是内置的 `DEFAULT_VHOST_HTTPS` 和 `etc\` 里发布的模板并不一致：**没有
80→443 跳转块，也没有 `ssl_ciphers` / `ssl_session_timeout` / `ssl_prefer_server_ciphers`**。
也就是说 v1.5.3 之后新建的 HTTPS 站点一直缺跳转。已改为从
`etc\nginx\vhosts\` 读。

### 3. 总览页组件行重叠、清空日志被切掉

- 组件行原本硬编码 `y = 112 + i * 40`。四个组件时最后一行落在 232，下面的按钮
  行在 264，本来刚好；加到五个后第 5 行落到 272，**直接压在按钮行上**。改为
  按 `Comp::Count` 推算行距，夹在「全部启动」行和按钮行之间，并限制上下限——
  以后再加组件也不会再撞
- 客户区实测 513px，而「清空日志」按钮底边在 518，**正好差 5px 被切掉一半**。
  窗口 560 → 610，总览与组件页的日志框加高，消除了组件页底部那条空白带

## 升级提示

- 附件是**压缩包**（v1.5.1 及之前发的是裸 `lnpp.exe`），请先解压再运行
- `bin\` 不在包内：把组件二进制放回 `bin\<组件>\<版本>\`（PHP 是
  `bin\php\<版本>\`，需含 `php-cgi.exe` 与 `ext\`），或编辑 `data\packages.conf`
  填入 https 源后用首次启动弹出的下载器安装
- **`data\settings.ini` 里的 `pg.password.enc` 绑定当前 Windows 账号，换机器或
  换用户需要重新填写库口令**
- 想要 PHP 站点的话，把 PHP 的 Windows 压缩包解压到 `bin\php\<版本>\`，到
  「PHP」页签点启动；然后在 nginx 页签添加站点时类型选「PHP（FastCGI）」
