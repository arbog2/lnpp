## LNPP 组件管理器 v1.5

自 v1.4 以来的更新（含 v1.4 Release 中标注的 2026-09-10 修订）。

### pm2 / Node.js
- 守护进程加固：所有 pm2 操作先校验守护进程存活（校验 `pm2.pid` 背后的进程镜像，避免 PID 复用误判）；只读命令在守护进程不在时不再调用 pm2，杜绝"查询顺手把守护进程拉起来"
- `\\.\pipe\rpc.sock` 握手失败（`EPERM`/`EPIPE`，通常由守护进程被强制结束、`pm2.pid` 残留引起）会自动等待并重试一次；仍失败时给出可操作提示，而不是 pm2 的原始堆栈
- 守护进程存活但应用列表为空时不再误判为「已在运行」，会真正执行 `resurrect`，应用不再"永远回不来"
- 列表按真实 pid 校验：pm2 报 `online` 但进程已不存在的行标记为「僵死：进程已不存在」，不再显示成内存为 0 的正常进程
- 启动 Node.js 前，若 Redis 已安装但未运行会先拉起 Redis，避免应用因 `6379` 未监听而启动即退

### 稳定性与安全
- 退出不再卡顿：`WM_DESTROY` 不再同步停止全部组件（原先最长要等 `pg_ctl -w` 30s 与 `pm2 kill`），只处理真正在运行且未被退出流程接管的组件
- 进程捕获收紧句柄继承（`STARTUPINFOEX` + `PROC_THREAD_ATTRIBUTE_HANDLE_LIST`），并发的 `runProcessCapture` 不再互相拖住
- 修复 `compStart` 每次启动泄漏一个进程句柄
- PostgreSQL 口令：明文 `pg.password` 首次读取即迁移为 DPAPI 密文；同时修掉密文尾部多写一个 NUL 字节的问题（旧密文仍可正常解密）
- nginx 新增站点：端口做数字校验；`nginx -t` 失败时回滚配置、运行时副本以及本次自动创建的 `www\<站点>` 目录
- `pgInit` 拒绝含换行的密码；`exeDir()` 改为线程安全；后台轮询不再重写 `nginx.pid`；「全部启动/停止」跳过正在执行操作的组件

### 其他
- 日志轮转：nginx / redis / PostgreSQL 日志超过 8MB 轮转并保留 2 代（在组件停止时进行），`logs\lnpp.log` 超过 4MB 轮转
- 下载进度消息节流；清理死代码（`runWait` / `redisTestConfig`）；`src/process.h` 改名 `src/proc.h`，避免遮蔽 CRT 的 `<process.h>`
- 验证：`/W4 /permissive-` 零警告；`test.bat` 四个测试套件全绿（含 PostgreSQL 17→18→17 数据迁移）
