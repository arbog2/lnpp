## LNPP 组件管理器 v1.5.5

一次针对 v1.5.4 的**审查修复版**：把 PHP 集成上线后暴露的 1 个必修缺陷、8 个重要
缺陷和 20 项健壮性问题一并修掉。核心是 **PHP 相关操作不再会打挂 nginx**。

没有新功能。**从 v1.5.4 升级只建议、不强制**——但如果你在用 PHP 站点，这个版本
修掉了几个会让人以为「管理器坏了」的问题。

### 必修：总览页的 PHP 行是死按钮

组件行按编号寻址（`710 + 组件序号`），而「关于」链接的控件 id 恰好也是 **714**——
正是 PHP（第 5 个组件，序号 4）那一行「启动/停止」按钮的编号。后果：

- 点 PHP 行的「启动/停止」**没有任何反应**（消息被「关于」的处理分支吃掉，
  而通知码对不上，于是静默丢弃）
- PHP 行的「随管理器启动」复选框压根没有处理分支
- 托盘的 PHP 菜单却是好的 —— 形成「托盘能切、总览不能切」的怪现象

同时补上编译期护栏：总览的固定控件 id 只要落进组件行的编号区间就**编译失败**，
并且组件数超过 6 个也会编译失败（再多就会压到下面的按钮行）。
这类「加个组件就悄悄顶掉别的控件」的问题以后不会再溜进来。

### 重要修复

**改进程数会打挂 nginx（最需要留意的）**

站点配置里的 `fastcgi_pass` 在创建时就写死了：单进程写 `127.0.0.1:9000`，多进程写
upstream 名。而改进程数以前只重生成主配置，**不改写已有站点**。于是把进程数从
多改回 1 之后，站点仍引用一个已经不再生成的 upstream，`nginx -t` 报
`unknown upstream`，**此后每次启动、重载、切版本都失败**，且必须手工重建站点才能
恢复。反过来（1 改多）则是站点被默默钉在单端口上，连接池白建。

现在改进程数会先重写引用该版本的**所有站点**的 `fastcgi_pass`（地址 ↔ upstream
名互换），再重载 nginx；重写失败会明确报错而不是留下半截状态。

**每次生成配置都刷屏的假告警**

`reportVhostDefaultServers` 用子串查找且不剔除注释，但两套 HTTPS 站点模板的注释里
本身就写着「这里不要写 default_server」——渲染后这段话会进每个站点文件。于是
**每个 HTTPS 站点每生成一次配置就产生 2 条「请删除该关键字」**，用户照做也只能删
注释，真正手写的违规反而被淹没。现在按行扫描，跳过注释行与行尾注释，并要求词边界。

**PHP「扩展管理」的两个问题**

- 点「应用并重启」时如果 PHP 正在启动/停止，操作会被**静默丢弃**，但对话框照样
  关闭 —— 看起来像「已应用」，实际什么都没写。现在会明确提示并保持窗口打开
- 扩展行只能用鼠标点：键盘（空格/回车）无法切换，点空白区域还会翻转当前选中行。
  现在鼠标、双击、空格、回车都能切换，且只认被点击的那一行

**PHP 停止前的依赖提示**

以前停掉一个被站点引用的 PHP 版本，站点直接变 502 且没有任何解释。现在会先列出
会受影响的站点名，默认按钮是「否」。这套「哪些站点依赖该端口」的判断以前是**死
代码**（函数写好了没人调用），现在真正接上了。

### 其它修复

| 问题 | 后果 |
|---|---|
| 多进程启动时中途失败不收尸 | 留下孤儿 php-cgi 占着端口，之后每次启动都失败，得手工杀进程 |
| 端口被别的程序占用时谎报启动成功 | 界面显示「运行中」，实际不是本管理器拉起的进程，站点 502 |
| 改进程数在界面线程跑 `nginx -t` + reload | 整个窗口冻结数秒（nginx 超时可达 10 秒） |
| 状态轮询不刷新 PHP 池 | 常驻 PHP 页签时，php-cgi 崩了界面仍显示「运行中」 |
| 端口分配的跳步逻辑 | 会跳过本可用的端口；极端情况下误报「没有空闲端口可分配」——**v1.5.4 的 PHP 首次启动分配端口就会踩中** |
| 端口被 `0.0.0.0` 通配监听时判为空闲 | 交给用户一个绑定必然失败的 php-cgi |
| upstream 名净化会碰撞 | `8.1` 与 `8_1` 得到同名 upstream，nginx 报致命错误 |
| `etc\php\php.ini.append` 缺失即锁死该版本 | 现在有内置默认追加段，PHP 仍能启动 |
| 扩展写回改动用户文件 | 重排 `extension = curl` 的空格、把 CRLF 改成混合换行；现在只增删那个分号 |
| 站点依赖判断用裸子串 | 端口 900 会命中所有 9000 的站点，注释掉的配置也算 |
| 归属判定的长路径/权限失败被静默跳过 | 杀不掉自己的进程却把原因归给「外部程序」 |
| 总览行距与「清空日志」 | 见上一版；本版补了编译期护栏防止回归 |

### 文档

- README 修正与代码不符的描述：组件数量（四种 → 五种，含 php）、发布包模板数
  （5 → 9）、包体积（约 300KB → 约 350KB，v1.5.4 实测 354.6KB）、
  `nginx.conf.tpl` 的占位符列表（删掉模板里并不存在的两项）
- 单测不再声称「不碰端口和磁盘」——它确实会只读地探测 TCP 表、读 `etc` 下的真实
  模板与用户的 `settings.ini`，注释已改为如实描述；测试改动的 ini 键一律按原值
  还原（以前是直接删除，将来若加上刷盘就会删掉用户配好的端口）

### 验证

- `/W4 /permissive-` 零警告（含新增的 id 唯一性与组件数上限 `static_assert`）
- `test.bat run` 全绿，新增断言覆盖：端口区间不重叠、空闲端口可分配（v1.5.4 的
  分配缺陷）、upstream 名净化与碰撞、扩展行解析与**写回保真**（注释、缩进、
  `extension = x` 的原始空格、CRLF、重复应用幂等）、`dirIsUnder` 的全部分支
- 逐条核对了审查报告的全部 29 项（1 个 P0 + 8 个 P1 + 20 个 P2）

### 升级提示

- 附件是**压缩包**，请先解压再运行
- `bin\` 不在包内：把组件二进制放回 `bin\<组件>\<版本>\`（PHP 是
  `bin\php\<版本>\`，需含 `php-cgi.exe` 与 `ext\`），或编辑 `data\packages.conf`
  填入 https 源后用首次启动弹出的下载器安装
- **`data\settings.ini` 里的 `pg.password.enc` 绑定当前 Windows 账号，换机器或
  换用户需要重新填写库口令**
- 如果你在 v1.5.4 上给某个 PHP 版本配了**多进程**，升级后第一次点「启动选中」会
  自动把相关站点的 `fastcgi_pass` 改写成对应的 upstream 名，无需手工干预
