## LNPP 组件管理器 v1.5.1

v1.5 → v1.5.1（pm2 守护进程风暴修复 + 实例列表可观测性）。

### 修复：pm2 守护进程风暴
- **判据根治**：从「`pm2.pid` 指向的进程是否存活」改为「RPC 管道 `\\.\pipe\rpc.sock` 是否可连接」。旧判据在 pidfile 陈旧（指向一个活着的 node 进程、但管道并不存在）时仍判定为"可用"，于是每次调用都让 pm2 CLI 自己再拉起一个守护进程，而新守护进程抢不到管道又失败，形成持续放大的循环
- **去掉故障期重试**：v1.5 在握手失败后会重试一次，在故障态会把守护进程创建速率翻倍，等于给风暴加油。现在失败即退避
- **新增 30 秒冷却熔断**：启动失败或管道握手失败后暂停所有 pm2 调用，任一命令成功立即解除；只读命令在守护进程不可用时直接返回空，写命令只给一次预热机会
- **提示可操作化**：告知管道不可用、已暂停调用、请稍后重试或结束残留守护进程，不再抛出 pm2 原始堆栈

### 新增：Node 页实例列表三列
- 新增 `PID`、`存活`、`僵死` 三列（列宽重新分配为 45/150/200/70/60/60/75）
- `状态` 列回归纯 pm2 状态，不再拼接后缀
- 僵死判定：pm2 报 `online` 但 pid 对应的进程已不存在（含 PID 复用防护），避免把已死的应用显示成正常进程

### 一并包含
- 守护进程存活但应用列表为空时不再误判「已在运行」，会真正执行 `resurrect`
- 启动 Node.js 前若 Redis 已安装但未运行，会先拉起 Redis，避免应用因 `6379` 未监听而启动即退

### 验证
- 故障态（陈旧 pidfile + 无管道）：`nodePm2List()` 返回空且**新造 0 个守护进程**；修复前会持续 spawn
- 健康态：返回真实应用（pid 有效、`stale=no`），12 秒内守护进程数稳定为 1
- `/W4 /permissive-` 零警告；`test.bat` 四个测试套件全绿（含 PostgreSQL 17→18→17 数据迁移）
