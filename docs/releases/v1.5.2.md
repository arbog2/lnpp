## LNPP 组件管理器 v1.5.2

v1.5.1 → v1.5.2。两项必修缺陷（其中一项有生产日志实证）+ 一项 nginx 安全加固。

### 修复：开机自启时 Redis 反复起不来（有日志实证）
`writeFileText` 的「临时文件 + 原子替换」用的是固定临时名 `<目标>.tmp` 且以
**独占方式**（share mode 0）打开。两个线程写同一目标时，后一个必然拿到
`ERROR_SHARING_VIOLATION` 而整体失败。开机自启时四个组件各起一个线程并发
`compStart`，而 `compStart(Nodejs)` 内部又会去 `compStart(Redis)`，于是
`genRedisConfig()` 被并发进入——`logs\lnpp.log` 里 2026-09-23 / 09-24 / 09-25
连续三天记着同一条 `启动 Node.js 前自动启动 Redis 失败: 生成 redis 配置失败`。

- 临时名改为带 pid-tid-序号，用 `CREATE_NEW`（永不打开已有文件）
- 遇 sharing / access / lock violation 退避重试 3 次（杀毒软件扫描同样会触发）
- **失败原因不再被吞掉**：`GetLastError()` 写进 `logs\lnpp.log`
- 另加两道防线：三个 `gen*Config()` 加生成互斥；`compStart` / `compStop` /
  `compSwitchVersion` 加每组件递归互斥，冲突方快速失败并给出可读原因

回归测试：8 线程并发写同一文件的用例，修复前 `ok=1/8`，修复后 `ok=8/8`。

### 修复：版本下拉框栈缓冲区溢出
「切换版本」用 `CB_GETLBTEXT` 往 128 字节栈缓冲拷贝，而该消息**不携带目标容量**，
控件按调用方的说法写。版本名来自 `bin\<组件>\<目录名>`，磁盘上一个长目录名即可溢出。
改为先问 `CB_GETLBTEXTLEN` 再拷贝。（全项目无界拷贝审计后仅此一处。）

### 新增：拒绝 IP 直连与未配置域名
多域名共存时，浏览器直接输 IP、或输一个没配置的域名，请求原本落到「该端口上第一个
server 块」——也就是某个业务站点。实测改动前：`https://<本机IP>/` 会**返回 200** 并
把站点原样端出来（因为该站点占着 `443 default_server`）。

主配置里加入一对兜底块：`:80` 未匹配 Host → `return 500`；`:443` 未匹配 SNI →
`ssl_reject_handshake`（握手阶段拒绝，**不需要给兜底块配证书**）。
`settings.ini` 的 `nginx.block_unknown_host=false` 可一键回退到原行为。

- 站点不再允许写 `default_server`：既会让未知域名命中该站点，也会与兜底块冲突导致
  nginx 报 `a duplicate default server for 0.0.0.0:443` 而起不来（顺带修好了
  「第二个 HTTPS 站点根本加不上去」这个 bug）
- 生成配置时扫描站点配置，发现 `default_server` 就在日志里点名是哪个文件第几行
  （`nginx -t` 只会说端口）
- 兜底块占用 80 / 443 但**不算端口冲突**，站点照常可放这两个端口

实测（临时实例，端口右移，未影响线上）：IP 直连与未配置域名 → 500；两个已配置域名
→ 301 正常；HTTPS 两种情形 → 握手被拒。

### 安全加固
- **Redis 只监听 127.0.0.1**：模板此前没有 `bind` 指令，Redis 5 因此监听所有网卡，
  而模板不带 `requirepass`——同网段任何人都能直连
- 下载源**强制 https**（此前 `http://` 会被照单全收）
- `packages.conf` 的版本号加白名单：此前 `nginx-../../evil` 能通过解析，
  解压结果会被复制到 `bin\nginx\..\..\evil`
- 读用户 PATH 失败时不再按「空 PATH」回写（那会把整个 PATH 覆盖成只剩 node 目录）
- `pgInit` 拒绝空密码（此前会建出无口令 superuser）
- 日志编辑框加上限，组件日志与备份有清理策略（见下）

### 顺带修掉的既有缺陷
- **`packages.conf` 分组解析错位**：标题写在 `---` 之前时会被挂到一个空分组上，
  真实分组全部丢标题，下载弹窗还会多出一个没有行的幽灵表头
- **UTF-8 BOM 毒化**：现代记事本保存 UTF-8 **带 BOM**，会让 `settings.ini` 的第一个
  键变成 `\ufeffver.nodejs` 而静默失效
- **ACP 回退是死代码**：`MultiByteToWideChar` 少传 `MB_ERR_INVALID_CHARS`，GBK 配置
  文件一直被当 UTF-8 读成乱码
- `nodePm2Cmd` 的 `pm2.js` 回退分支此前把 `.js` 当 exe 传给 `CreateProcess`
  （必然错误 193），现在正确走 `node.exe`
- pm2 熔断计时改为原子量；`redisPort` 补端口校验；`nginxListVHosts` 不再命中
  `document_root`；嵌入 manifest（DPI 感知 + ComCtl32 v6，高缩放下不再发虚）

### 工程
- **测试套件不再破坏真实环境**：`test.bat` 默认只跑 `unittests`；
  `selftest` / `proctest` / `migtest` 改为显式触发并打印警告。`migtest` 此前会
  重建真实数据库、且断言了一个它自己从不创建的表（换机必假失败），`selftest` 会把
  nginx 切到另一个版本且不还原——现在都修了。退出码 `2` 表示「跳过」，不再被算作通过
- `unittests` 从 30 条扩到 100+ 条：新增 `packages.conf` 语法、并发写、DPAPI 往返、
  文件编码、版本排序边界、nginx 兜底块渲染等用例
- 新增 `package.bat`：按白名单打出自检式发布包，压缩前核验不含 `bin/ data/ logs/
  backup/ ssl/` 与站点配置
- 迁移产物清理：`data\postgresql\*.old-*` 与 `backup\*.sql` 超量部分移入回收站
  （可撤销），保留数由 `keep.datacopies` / `keep.backups` 调整。本机此前堆积 32 份共 3.9 GB
- `check-cert.ps1` 去掉硬编码路径：此前写死 `bin\nginx\1.30`，在只装了 1.30.4 的机器上
  存在性检查恒为假，脚本里的 `nginx -t` **从未真正执行过**

### 验证
- `/W4 /permissive-` 零警告；`test.bat run` 100+ 断言全绿
- 冒烟启动无异常，`logs\lnpp.log` 无新增错误（此前每天一条自启失败）
- nginx 兜底块行为已在隔离实例上实测（见上）

### 升级提示
本版附件是**压缩包**（v1.5.1 及之前发的是裸 `lnpp.exe`），请先解压再运行。
`bin\` 不在包内：把组件二进制放回 `bin\<组件>\<版本>\`，或复制包里的
`packages.conf.example` 为 `packages.conf` 填入 https 源，用首次启动弹出的下载器安装。
`data\` 里的 `pg.password.enc` 绑定当前 Windows 账号，**换机器或换用户需要重新填写库口令**。
