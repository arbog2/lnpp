## LNPP 组件管理器 v1.5.3

磁盘布局重构 + PostgreSQL 还原功能。**`etc\` 只放模板，`data\` 放一切运行时状态**——
升级时站点配置与下载源会自动迁移，无需手工操作。

本版三块内容：目录布局重构（§1–§3）、PostgreSQL「还原数据库」（§4）、
两个 nginx 配置修复（§5）。

### 为什么改

此前 `etc\` 里混着用户数据：站点配置（`jwxt.conf` / `pk.conf`，含内网域名和
`D:/code/jwxt/public` 这类绝对路径）就放在模板旁边。而 `etc\` 正是随发布包分发的目录
——只要打包时图省事复制一下 `etc`，这些内容就会跟着发出去。

拆开之后 `etc\` 里只有模板，**误打包在结构上不可能发生**：发布包里
`etc\nginx\vhosts\` 只有一个 `_template*.conf`，没有任何用户站点配置。

### 新的目录约定

```
etc\                      只放模板，随包分发、只读
  nginx\nginx.conf.tpl
  nginx\vhosts\_template.conf / _template_https.conf
  postgresql\postgresql.conf.append
  redis\redis.conf.tpl
  packages.conf.tpl       组件下载源模板
data\                     全部运行时状态，缺失时首次运行自动创建
  settings.ini            版本选择 / 端口 / DPAPI 加密的库口令
  packages.conf           下载列表（由模板生成，可直接改）
  nginx\vhosts\*.conf     站点配置
  nginx\<版本>\conf\      各版本运行配置
  postgresql\<版本>\  redis\<版本>\
```

### 升级时自动做什么

首次启动时（升级后第一次运行）自动完成，无需手工干预：

1. `data\` 不存在就创建
2. 从 `etc\packages.conf.tpl` 生成 `data\packages.conf`
3. 把 `etc\nginx\vhosts\*.conf` 迁到 `data\nginx\vhosts\`——**先复制，确认复制出来
   能读出来，才删原件**；已存在同名文件一律不覆盖。模板文件（`_template*`）留在 `etc\`
4. 根目录旧的 `packages.conf` 迁进 `data\`

迁移会在 `logs\lnpp.log` 留下记录。本机实测：2 个站点配置迁移完成，内容与运行副本
SHA256 逐字节一致。

### 需要你知道的两个路径变化

- **改站点配置请改 `data\nginx\vhosts\`**，不再是 `etc\nginx\vhosts\`。启动时会从这里
  复制到每个版本的运行前缀（`data\nginx\<版本>\conf\vhosts\`）——这个复制不能省，
  因为 nginx 的 `include vhosts/*.conf` 是相对 `-p` 前缀解析的。**在运行副本里改会被
  下次启动覆盖。**
- **下载源改 `data\packages.conf`**。v1.5.2 还需要把 `packages.conf.example` 手工改名，
  本版自动生成，直接编辑即可。

### 「配置」按钮改为打开运行时配置目录

原先它打开 `etc\` 模板目录——在新布局下那是一堆运行时根本不读取的文件，Node.js 更糟：
`etc\nodejs\` 压根不存在。现在指向真正会被读取、手工可改的配置：

| 组件 | 打开的目录 |
|---|---|
| nginx | `data\nginx\vhosts\`（站点配置源，**不是**每版本运行副本） |
| PostgreSQL | `data\postgresql\<当前版本>\` |
| Redis | `data\redis\<当前版本>\` |
| Node.js | `data\nodejs\`（附提示：pm2 自己的文件在 `%USERPROFILE%\.pm2`） |

目录不存在会按需创建，失败时给出提示而不是静默无反应。

### 新增：PostgreSQL「还原数据库」

PostgreSQL 页签新增「还原数据库」按钮：列出 `backup\` 下的 `pg_dumpall` 备份（按时间
倒序，显示时间与大小），选一个回灌。流程全部跑在工作线程，界面不卡（psql 最长等 30 分钟）。

- **「还原前初始化」复选框**（默认不勾）：勾上会先重建数据目录——当前所有数据库与
  角色清空。**这一步不可撤销**，但原数据目录是 `MoveFile` 到
  `.before-restore-<时间戳>` 保留的，不是删除。
- **不勾也能用**：直接在现有集群上回灌，dump 里不存在的库不会被删。
- **两次确认**：打开对话框前一次；勾了「初始化」再弹一次，写明备份文件、目标版本、
  "此操作不可撤销"，以及"原目录会被移到一边保留"。两个确认框的默认按钮都是「否」。
- **失败自动回滚**：initdb / 启动 / 回灌任何一步失败，停库、移走半成品目录、还原原
  数据目录并重新启动，错误里说明回滚结果。
- **判定成败靠 SQLSTATE 而非错误文本**：dump 必然撞上引导超级用户（它存在于任何集群，
  initdb 刚建的也一样），所以 psql 不加 `ON_ERROR_STOP`，改为按 `42710
  duplicate_object` + 出错语句判断——只有「角色/数据库已存在」算良性，**表已存在一律
  判失败**（那说明 dump 正在往还留着旧数据的集群里合并）。判据不含自然语言，
  `lc_messages` 改成中文也不受影响。
- 还原前的集群副本计入 `keep.datacopies` 清理策略（此前只认 `.old-` / `.failed-`，
  还原产生的副本永远清不掉）。

### 修复：GUI 新建的 HTTPS 站点无视 nodejs.port

`_template_https.conf` 把 `proxy_pass` 写死 `127.0.0.1:3000`，而生成器明明传了
`{{NODEJS_PORT}}`（非 HTTPS 模板用的就是占位符）。经界面新建的 HTTPS 站点一律打到
3000，与 `settings.ini` 的 `nodejs.port` 无关。手写的站点配置不受影响。

### 修复：站点端口冲突判定

两处都不准：

- 冲突检查只读每个站点文件的**第一个** `listen`。HTTPS 模板首行是 `listen 80` 的跳转
  块，于是所有 HTTPS 站点都被记成 80——443 上的真冲突看不见，两个同在 80 的 HTTP 站点
  反被判为冲突。现在取全部监听端口。
- 判定本身也不对：nginx 里「同端口 + 不同 `server_name`」是**合法**的多域名布局
  （兜底块本来就是为它设计的），原逻辑却直接拒绝。现在只有**同端口 + 同域名**才算冲突；
  共端口不同域名放行，并在日志里记一笔。

### 验证

- `/W4 /permissive-` 零警告；`test.bat run` 100+ 断言全绿
- `unittests` 新增**布局断言**：站点配置与下载列表必须在 `data\` 下、模板必须在 `etc\` 下、
  两者路径不同、nginx 的配置目录不得是 `conf\vhosts`（每版本运行副本）——防止以后有人
  把站点配置又写回 `etc\`
- `unittests` 新增**还原判定断言** 13 条：verbose 形式、本地化形式（中文报错同样能区分
  角色/表）、表已存在必须被拒、良性错误不得掩盖后续真实错误、WARNING 不算失败
- 主窗口控件 ID 冲突加 `static_assert` 编译期护栏（详见提交 `b3dc98c`）
- 发布包 311 KB / 9 个条目，核验无 `data\` `ssl\` `bin\` `settings.ini` 与任何用户站点配置；
  打包脚本对 6 个模板逐个判失败，缺一个即中止（负向验证过）
- `unittests` 跑完 `%TEMP%` 零残留

### 升级提示

- 附件是**压缩包**（v1.5.1 及之前发的是裸 `lnpp.exe`），请先解压再运行
- `bin\` 不在包内：把组件二进制放回 `bin\<组件>\<版本>\`，或编辑 `data\packages.conf`
  填入 https 源后用首次启动弹出的下载器安装
- **还原前请先备份**。勾了「还原前初始化」会清空所有数据库与角色；原数据目录会被保留
  在 `.before-restore-<时间戳>`，但别指望它——它会随 `keep.datacopies` 被清理
- `data\settings.ini` 里的 `pg.password.enc` 绑定当前 Windows 账号，**换机器或换用户
  需要重新填写库口令**
